# rules_rs metadata stub

`data.bzli` describes `DEP_DATA` in the root `data.bzl` generated by
[rules_rs 0.0.111](https://github.com/hermeticbuild/rules_rs/blob/v0.0.111/rs/private/cargo_workspace_graph.bzl#L602-L711).
Each workspace package has dependency lists, platform-specific dependency
maps, crate properties, and an optional lint configuration label.

Select the contract explicitly for the generated repository:

```sh
starpls check path/to/BUILD.bazel \
  --type_interface /path/to/generated/cargo/data.bzl=/path/to/starpls/stubs/rules_rs/data.bzli
```

The same mapping configures `starpls server`. The mapping is a trusted
contract selected by the consumer; check the generator version when
upgrading rules_rs. Generated repositories have their own identities, so
the selected rules_rs module version belongs to the generating extension.

Additional source exports use ordinary source inference. Downstream
extensions to the metadata schema can supply their own stub. Independent
`--validate-stubs` checking can report incomplete validation when source
inference aggregates the dictionary's field types.
